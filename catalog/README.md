# Catalog

`catalog/` contains generated discovery projections for Fabric Ecosystem.

```text
Catalog = derived discovery projection
Catalog != Fabric semantic truth
Catalog != registry
Catalog != package manifest authority
Catalog != runtime state
```

Fabric and Rust source own Resource APIs, Components, Adapters, relations,
Composition graphs, Host truth, and runtime behavior. Cargo manifests own Cargo
package metadata. Repository topology owns source placement. The Catalog
projects selected discovery facts from those owners.

## Generated Views

- `index.json`: machine-readable Catalog v1.
- `index.md`: human-readable navigation generated from the same in-memory model.

Both files are generated by:

```sh
cargo run -p fabric-ecosystem-catalog-tool -- write
```

Check committed output without mutation:

```sh
cargo run -p fabric-ecosystem-catalog-tool -- check
```

Workspace tests also run the same drift check.

## Consuming Catalog v1

`index.json` is the machine-readable Catalog contract. Local query commands read
the committed JSON projection directly; they do not run Cargo metadata, inspect
Rust/Fabric source, or materialize runtime state.

```sh
cargo run -p fabric-ecosystem-catalog-tool -- list
cargo run -p fabric-ecosystem-catalog-tool -- list-kind package
cargo run -p fabric-ecosystem-catalog-tool -- list-category networking
cargo run -p fabric-ecosystem-catalog-tool -- show packages/networking/http
cargo run -p fabric-ecosystem-catalog-tool -- show-package onoal-fabric-package-networking-http
cargo run -p fabric-ecosystem-catalog-tool -- deps compositions/web/http-server
cargo run -p fabric-ecosystem-catalog-tool -- dependents packages/networking/tcp
```

Query commands show the committed projection as-is. `check` remains the command
that validates whether committed output is fresh relative to repository/Cargo
sources.

## JSON V1

`index.json` uses:

```json
{
  "schemaVersion": 1,
  "artifacts": []
}
```

Each artifact entry contains discovery/navigation fields only:

- `kind`: repository artifact kind derived from path: `package`, `host`,
  `composition`, or `example`.
- `category`: open repository navigation category where the path has one
  (`packages/<category>/...`, `compositions/<category>/...`).
- `path`: repository-relative artifact source path.
- `cargoPackage`: Cargo package name from Cargo metadata.
- `version`: resolved Cargo package version from Cargo metadata.
- `description`: Cargo package description from Cargo metadata.
- `publishable`: derived from Cargo `publish` metadata.
- `readme`: repository-relative README path when `<artifact>/README.md` exists.
- `dependencies.normal`, `dependencies.development`, `dependencies.build`:
  direct Cargo dependency edges to other cataloged ecosystem artifacts, grouped
  by Cargo dependency kind and referenced by artifact source path.

There is no Catalog-owned artifact ID in v1. Repository-relative path and Cargo
package name already have concrete owners.

## Classification

Catalog v1 classifies workspace Cargo packages by repository path:

```text
packages/<category>/<artifact>        -> package
hosts/<artifact>                      -> host
compositions/<category>/<artifact>    -> composition
examples/<artifact>                   -> example
```

`tests/*` and `tools/*` are verification/tooling infrastructure and are not
cataloged ecosystem artifacts.

Repository artifact kind and category are navigation facts. They are not Fabric
semantic kinds.

## Dependency Meaning

Catalog dependency edges are Cargo dependency/navigation edges. They are not
Fabric relations, Resource requirements, Component dependencies, Composition
graphs, runtime dependencies, or semantic ownership claims.

External dependencies such as `onoal-fabric`, `rusqlite`, `httparse`, and
cryptographic crates are excluded unless they are themselves cataloged
repository artifacts.

## Non-Goals

Catalog v1 does not contain:

- Resource, System, Component, Adapter, Augmentation, Config, or relation IDs;
- handwritten `provides` / `requires` fields;
- maturity, stability, quality, status, recommendation, tag, or keyword
  taxonomies;
- runtime discovery or materialization results;
- generated timestamps, hostnames, user names, random IDs, absolute paths, or
  dirty-state information;
- remote registry, website, HTTP service, publication workflow, or package
  installer behavior.

Future views may consume a canonical Fabric definition projection if Fabric
exposes one. Until then, Catalog deliberately avoids Rust macro/source
introspection.
